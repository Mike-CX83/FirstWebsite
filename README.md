# First Website

## Project Description

A personal website introducing Mike Hankins, his education, interests, and family life. Built with HTML and CSS, this project demonstrates the fundamentals of organizing content across multiple pages, sharing a consistent design, and embedding photos and video.

## Usage / How It Works

Open the home page and use the navigation to explore four pages:

* **Home:** an introduction and education background.
* **Interests:** hobbies, photographs, and an embedded video.
* **Gallery:** a collection of personal photos and video.
* **Contact:** a form demonstrating text fields, email validation, and a newsletter checkbox.

Each page links to the same stylesheet. Media files are stored in the `images` directory, and Font Awesome supplies the social icons.

The contact form is a visual demonstration. It does not send messages or subscribe visitors to a newsletter because no backend is connected.

## Installation

You need a web browser. Git is optional if you download the repository as a ZIP.

1. Clone the repository:

```bash
git clone https://github.com/Mike-CX83/FirstWebsite.git
cd FirstWebsite
```

2. Open `index.html` in your browser.
3. Keep the other HTML files, `style.css`, and the `images` folder together so navigation, styling, and media paths work.

No package installation or build command is required. An internet connection is needed to load Font Awesome from its CDN. You can also open the folder in VS Code and use Live Server.

## Tech Stack

* HTML for page structure, navigation, forms, and media.
* CSS for shared styling.
* Font Awesome for social icons.

## Project Files

* `index.html`: home page.
* `interests.html`: interests page.
* `gallery.html`: media gallery.
* `contact.html`: demonstration contact form.
* `style.css`: shared design.
* `images/`: local images and video.

## Development Focus

This project practices relative file paths, navigation between pages, reusable CSS, and native HTML form controls. It provides a foundation for later projects that add frameworks and JavaScript.

## Current Limitations and Possible Improvements

The form needs a backend before it can deliver messages. Some page metadata still contains starter placeholders. Future improvements could include cleaning up that metadata, reviewing mobile layouts, and providing more descriptive media alternatives.
